# SDN DDoS Detection and Mitigation with Machine Learning

This repository implements a flow-based DDoS detector for an OpenFlow 1.3 network using Mininet and the Ryu controller. It contains a shared dataset preprocessing pipeline, a model benchmark, a saved-model inference path for the controller, flow-stat collectors, and optional exact-flow mitigation.

> **Important data note:** the uploaded repository did not contain the 10,000-flow dataset claimed in its old README. The two `FlowStatsfile.csv` files were broken path placeholders, and the documented `generate_realistic_dataset.py` was absent. This version does not claim those metrics as results. A clearly-labelled synthetic demo dataset is included only to test that the software pipeline works end to end.

## Hybrid temporal detector + staged mitigation (new)

A second, destination-centric temporal detection layer and a staged, reversible
mitigation system were added on top of the original flow-level model to fix its
false positives on legitimate high-volume UDP. The flow-level model and
`artifacts/production/` are **unchanged**.

- `ddos_ml/temporal_features.py` — OpenFlow counter-delta tracking (interval
  rates, not lifetime averages) + destination-centric window features.
- `ddos_ml/decision_engine.py` — explainable linear scorers + a
  `NORMAL→SUSPECTED→CONFIRMED→MITIGATING→RECOVERING` state machine + source
  attribution.
- `Codes/controller/hybrid_controller.py` — new Ryu app (the original
  `controller.py` is kept as the baseline/capture tool). Mitigation is **off and
  dry-run by default**; see `ddos_ml/config.py` and `experiments/configs/`.
- `experiments/` — seeded Mininet scenarios (A–G), campaign runner, offline
  replay, model fitting (calibration only), baseline/ablation evaluation,
  figures, and the paper tables. See **`experiments/README.md`**.
- `docs/` — `research_plan.md`, `architecture.md`, `dataset_audit.md`,
  `related_work.md`, `experimental_methodology.md`, `limitations.md`,
  `paper_outline.md`, and the auto-generated `results_summary.md`.

Why: the data audit (`docs/dataset_audit.md`) shows neither CIC-DDoS2019 nor
CSE-CIC-IDS2018 contains large-packet benign UDP, so no flow-level model can
separate it from a flood at the single-flow level — the discrimination must come
from destination-level temporal context. Run the full experiment pipeline from
`experiments/README.md`.

## What changed

- Replaced positional-column training with one named feature schema shared by preprocessing, training, and live Ryu inference.
- Excluded IP addresses, timestamps, flow IDs, datapath IDs, and ports from model inputs to reduce identity leakage and improve transferability.
- Added CICFlowMeter and original SDN/OpenFlow CSV support.
- Normalized labels to `0 = BENIGN`, `1 = DoS/DDoS`; numeric label inversion is configurable for datasets with the opposite convention.
- Handles NaN/Inf, malformed numeric cells, zero-duration flows, missing rate fields, and CICFlowMeter duration units.
- Added flow-group-aware holdout splitting. When endpoint fields exist, forward and reverse directions of the same 5-tuple are grouped together so a conversation cannot leak across train and test.
- Added a scikit-learn Pipeline so median imputation and scaling are fitted on training data only.
- Constrained tree depth and leaf sizes, and reports train/test F1 gap, FPR, balanced accuracy, ROC-AUC, average precision, and confusion matrices.
- The Ryu controller loads a saved model; it no longer retrains itself from a missing CSV or feeds a different feature shape at prediction time.
- Automatic mitigation is off by default and, when enabled, installs short-lived drop rules for exact flow matches rather than blocking an entire switch port.
- Removed the bundled `ddos-env` virtual environment and Git internals from the deliverable.

## 1. Environment setup

Recommended for the Ryu/Mininet part: Ubuntu 20.04 or 22.04 with Python 3.10. The ML pipeline can run on a regular Windows/WSL/Linux Python environment without Ryu or Mininet.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements-dev.txt
```

Install Mininet and Open vSwitch in the Ubuntu VM/host using the official Mininet instructions. Ryu is a legacy dependency; install it separately in a Python 3.10 environment:

```bash
pip install -r requirements-ryu.txt
```

Do not install Ryu into Python 3.12+ without checking compatibility. The Ryu integration was syntax-checked here but could not be executed because Ryu/Mininet/Open vSwitch are not installed in this environment.

## 3. Prepare a real dataset

### Recommended: original CIC-DDoS2019

Canonical dataset page (Canadian Institute for Cybersecurity):

https://www.unb.ca/cic/datasets/ddos-2019.html

CIC-DDoS2019 contains labelled CICFlowMeter-V3 flow CSVs for benign traffic and multiple DDoS families. The provider permits redistribution with the required dataset/paper citation. The official page links to a download portal that may ask for registration details.

**Alternative download helper:** a public Hugging Face mirror contains the published per-attack CSV names. The mirror lists 11 CSVs at approximately 22.3 GB total; it is not the canonical host. The default starter subset (`UDPLag.csv`, `Syn.csv`, `DrDoS_NTP.csv`) is approximately 1.44 GB. Download it with:

```bash
pip install -r requirements-download.txt
python scripts/download_cicddos2019.py
```

To download all 11 files (about 22.3 GB):

```bash
python scripts/download_cicddos2019.py --all
```

To choose exact attack CSVs:

```bash
python scripts/download_cicddos2019.py --files UDPLag.csv Syn.csv DrDoS_DNS.csv
```

Downloaded files are placed under `data/raw/CICDDoS2019/01-12/`. The public mirror is `baalajimaestro/CICDDoS2019` on Hugging Face; verify the source/version and retain the original CIC citation when using the data.

Preprocess all downloaded CSVs (the script reads in chunks, removes unrecognized labels and normalizes BENIGN to 0 and DDoS/DoS to 1):

```bash
python scripts/preprocess_dataset.py \
  --input data/raw/CICDDoS2019/01-12 \
  --output data/processed/cicddos2019_flows.csv
```

Then train the benchmark and export the production candidate:

```bash
python scripts/train.py \
  --input data/processed/cicddos2019_flows.csv \
  --output-dir artifacts/production \
  --max-rows 100000
```

The `--max-rows` cap is optional. It is a practical first run on a laptop; remove it for a larger run if memory and runtime permit. The trainer now refuses to fall back to a row-wise split when a `group_id` exists but cannot be safely separated. It reports group counts and asserts zero group overlap between train and test.

For a single SDN capture collected by the Ryu collector, use:

```bash
python scripts/preprocess_dataset.py \
  --input data/raw/sdn_flows.csv \
  --output data/processed/sdn_flows.csv
```

The preprocessor writes a `.summary.json` file with source files, rows read/kept, class counts, and errors.

### Label conventions

- This project's default: `0 = BENIGN`, `1 = DoS/DDoS`.
- String labels such as `BENIGN`, `DrDoS_DNS`, `Syn`, `UDP`, `DoS Hulk`, and `DDoS` are normalized.
- For datasets whose numeric labels are reversed, pass `--numeric-label-meaning one_is_benign`.
- Unrelated CICIDS attack classes (for example brute-force or web attacks) are excluded from the DDoS-focused binary task rather than silently relabelled as DDoS.

## 4. Train and evaluate the model

```bash
python scripts/train.py \
  --input data/processed/cicddos2019_flows.csv \
  --output-dir artifacts/production
```

Optional memory cap:

```bash
python scripts/train.py --input data/processed/cicddos2019_flows.csv \
  --output-dir artifacts/production --max-rows 250000
```

The benchmark compares Random Forest, Extra Trees, Decision Tree, Logistic Regression, KNN, Naive Bayes, and HistGradientBoosting. It reports:

- Accuracy and balanced accuracy
- Precision, recall, F1-score
- False-positive rate
- ROC-AUC and average precision
- Confusion matrix
- Train/test F1 gap as a basic overfitting indicator

The deployment baseline is a constrained Random Forest with maximum depth, minimum leaf size, feature subsampling, and class balancing. Do not select a model on accuracy alone; review DDoS recall and false-positive rate, especially before turning on mitigation.

Outputs:

```text
artifacts/production/
├── random_forest.joblib
├── model_metadata.json
├── metrics.json
├── metrics.csv
├── model_comparison.png
└── random_forest_confusion_matrix.png
```

## 5. Run the Ryu/Mininet controller

The controller loads the trained Random Forest from `artifacts/production/`. It does not train on startup.

Terminal 1:

```bash
source .venv/bin/activate
cd Codes/controller
ryu-manager --ofp-tcp-listen-port 6653 controller.py
```

Terminal 2:

```bash
cd Codes/mininet
sudo python3 topology.py 127.0.0.1
```

Generate benign traffic and then test a DDoS scenario from the Mininet CLI using the included traffic scripts. Start with a small, controlled lab topology and do not run flood commands against public or third-party hosts.

The controller polls OpenFlow stats, maps them to the same seven model features, and reports predictions. The default is detection-only.

### Optional mitigation

After validating the trained model on held-out and live lab traffic, run:

```bash
cd Codes/controller
DDOS_AUTO_MITIGATE=1 \
  ryu-manager --ofp-tcp-listen-port 6653 mitigation_module.py
```

Mitigation is off unless explicitly enabled. When enabled, it installs temporary drop rules for individual predicted flow tuples. It does not block an entire ingress port. Tune `DDOS_BLOCK_TIMEOUT` (default 30 seconds) and `DDOS_MAX_BLOCKS_PER_WINDOW` (default 20) for the lab environment.

## 6. Collect your own labelled SDN flows

The included Ryu collectors write to `data/raw/sdn_flows.csv` by default:

- `start_traffic_collection.py`: label 0 (benign)
- `collect_ddos_trafic.py`: label 1 (attack)

Capture benign traffic in a separate run, then stop the controller, preserve the file, and collect attack traffic with the attack collector. Do not run both collectors at once unless you deliberately want both labels written concurrently. Do not relabel all rows from a mixed capture based on the current terminal mode.

The output is compatible with the same preprocessing script. Set `DDOS_FLOW_CSV=/absolute/path/to/file.csv` to change the collector output path.

## Limitations and interpretation

- Public CICFlowMeter data is not captured from your exact Mininet topology. It is useful for model development but must be validated on a separate labelled capture from the target SDN setup before deployment.
- Group-aware splitting reduces duplicate-flow leakage, but it does not prove that a model generalizes to a new topology, device mix, or attack family.
- The included synthetic demo is not real-world evidence.
- Ryu/Mininet/Open vSwitch integration still needs a run in the user's Ubuntu lab; those services are not installed in the validation environment used to prepare this archive.
